# 11/7 시험에서 나온 문제와 할 일

기준: 제출본 `컴학감동_미션2_실손보험 청구 서류 검증` 설정 #9. 팀원 A·B의 시험 결과(11/7)를 정리했다.

## 공통 규칙

- **제출본은 고치지도 실행하지도 않는다.** 시험은 각자 복사본에서 한다. 효과가 확인되면 혁진이 제출본에 하나씩 옮긴다.
- 한 사람이 1~4번을 모두 맡는다. 복사본은 제출본 **설정 #9를 새로 복사**해 하나만 쓰고, 이름 끝에 `(시험용 이슈)`를 붙인다.
- **순서: 1 → 3 → 2 → 4 → 6.** 1과 3은 같은 프롬프트 수정이라 한 번에 시험한다. 2는 분류 구조를 바꾸므로 1·3을 끝낸 뒤 한다.
- 가상 문서만 쓴다. 실제 서류는 올리지 않는다.
- 보고 형식: `설정 번호 / 파일 / 작업 ID / 결과 / 기대값과의 차이 / 추출 캐시 재사용 여부`
- 출력 키 7개(`patient_name`, `provider_name`, `decision`, `cause`, `reason`, `missing_documents`, `mismatches`)는 바꾸지 않는다.

## 요약

| 순서 | # | 문제 | 위험 | 상태 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 판정 값 뒤에 인용 표시 `【†17】`가 붙음 | **매우 높음** | 시험 필요 |
| 1 | 3 | 빈 이름을 "빈 값"이라는 글자로 쓸 위험 | 중간 | 1번과 함께 시험 |
| 2 | 2 | 빈 페이지가 섞이면 청구 전체가 실패 | **높음** | 시험 필요 |
| 3 | 4 | 반복 실행이 추출 결과를 재사용함 | 중간 | 확인 필요 |
| 4 | 6 | 사전 설문 질문 추가 | - | 초안 → 혁진 제출 (11/9 오전 10시) |
| - | 5 | 총액 칸이 빈 영수증을 못 잡음 | 높음 | **한계로 확정, 작업 없음** |

1·3번 결과가 나오면 혁진에게 먼저 보낸다. 인용 표시는 채점에 바로 영향을 줄 수 있어 제출본에 빨리 반영해야 한다.

## 1. 판정 값 뒤 인용 표시

**무슨 문제인가**
`청구_판정` content의 값 뒤에 인용 표시가 붙는다. 5건 중 3건에서 나왔다.

```text
decision: 심사 진행【†17】
cause: 없음【†18】
missing_documents: []【†19】
mismatches: []【†20】
심사 진행【†21】
```

- 나온 파일: `시험_A7_합계만따로_일치.pdf`(전부), `시험_A4_괄호서식_정상.pdf`(전부), `시험_A4_간이서식_정상.pdf`(decision과 마지막 줄)
- 같은 결과의 metadata enum은 `심사 진행`으로 깨끗하다
- `scripts/score_studio.py`로 채점하면 decision, cause, missing_documents, mismatches가 모두 틀림. 표시를 빼면 모두 일치
- **공식 채점이 이 표시를 지우는지 모른다.** 지우지 않으면 해당 케이스가 통째로 틀린다

**할 일**
1. 복사본 `청구_판정` 노드 설정에 출처·인용·근거 표시를 끄는 옵션이 있는지 찾는다. 있으면 끄고 2번은 건너뛴다.
2. 옵션이 없으면 프롬프트의 출력 형식 바로 위에 아래 문장을 넣는다.
   ```text
   각 줄의 값 뒤에는 아무것도 붙이지 않는다. 【†숫자】 같은 인용 표시, 출처 번호, 각주를 쓰지 않는다.
   ```
3. 3번의 출력 형식 수정도 같은 설정에 함께 넣는다.
4. 인용 표시가 나왔던 파일 3개와 set01~05를 각 3번 실행한다.

**끝난 기준**: 인용 표시가 0번 나오고, 판정이 기대값과 같다. 실행별 content 원문을 함께 보고한다.

## 2. 빈 페이지가 섞이면 청구 전체가 실패

**무슨 문제인가**
`시험_B_영수증_빈페이지.pdf`(영수증 + 빈 페이지)에서 판정이 나오지 않았다. 1번 실행했다.
- 작업: `job_7Jjvqa8jDHTeSNdyH4TMQw`
- 상태: Parse·Classify 완료, Extract 취소, Instruct 실패
- 오류: `No text elements were detected in the input file.`
- 판정 노드 content가 없어 이 파일은 실행 정확도에서 0점이 된다

**추정 원인 (미확인)**
낱장 분리로 빈 페이지가 `Other`가 되고, `미분류_안내`가 글자 없는 쪽에서 실패한다. 설정 #9부터 `미분류_안내`가 `병합-1`에 연결돼 있어서, 이 실패가 같은 파일의 영수증 판정까지 막는 것으로 보인다.

**할 일**
1. 같은 파일을 2번 더 실행해 재현되는지 확인한다.
2. 재현되면 아래 방법을 차례로 시험한다. 하나씩 바꾸고 실행한다.
   - A. Classify에 클래스 `blank`를 추가한다. 설명: "글자가 없거나 거의 없는 빈 페이지". 어떤 노드에도 연결하지 않는다.
   - B. A가 안 되면 `Other` 설명에서 "빈 페이지"를 빼고, `blank`로만 가게 한다.
3. 바꾼 뒤 아래를 각 2번 실행한다.
   - `시험_B_영수증_빈페이지.pdf`: 기대 **심사 진행 / 없음 / [] / []**
   - `시험_기타문서만.pdf`: 기대 **보완 요청 / 서류 누락 / ["진료비 영수증"] / []**
   - set01~05: 정답지와 같아야 함

**끝난 기준**: 빈 페이지가 있어도 판정이 나오고, 기존 파일의 판정이 바뀌지 않는다. 안 되면 "최종 데이터셋에 빈 페이지를 넣지 않는다"로 정리한다.

## 3. 빈 이름 표기 (1번과 같은 수정에서 함께 시험)

**무슨 문제인가**
- 정답지에 빈 이름은 `""`로 적어야 채점 스크립트가 일치로 읽는다. `null`이면 틀림
- Studio 출력이 `patient_name:`처럼 콜론 뒤가 비어 있어야 일치한다. `빈 값`, `없음`, `-`로 쓰면 틀림
- 지금 프롬프트는 `<영수증 환자 이름. 영수증이 없으면 빈 값>`이라 모델이 "빈 값"이라는 글자를 쓸 위험이 있다

**할 일**
1. 출력 형식 두 줄을 아래처럼 바꾼다.
   ```text
   patient_name: <영수증 환자 이름. 영수증이 없으면 콜론 뒤에 아무것도 쓰지 않는다>
   provider_name: <영수증 요양기관. 영수증이 없으면 콜론 뒤에 아무것도 쓰지 않는다>
   ```
2. `시험_기타문서만.pdf`, `시험_B_수납대장만.pdf`, `시험_B_흐린문서만.pdf`를 각 3번 실행한다.

**끝난 기준**: 세 파일 모두 `patient_name:`, `provider_name:` 뒤가 비어 있다.

## 4. 반복 실행의 추출 캐시

**무슨 문제인가**
같은 파일을 다시 실행하면 `영수증_추출` 결과를 재사용하는 경우가 많다. 그래서 지금까지의 반복 실행은 **판정 단계의 흔들림**만 본 셈이고, 추출이 흔들리는지는 거의 시험하지 못했다.

**할 일**
1. 추출을 새로 하게 만드는 방법을 찾는다. 예: 같은 PDF를 다른 이름으로 다시 올리기, 추출 설정을 바꾸고 되돌리기
2. 찾으면 set02, set04, `시험_읽기오류_검산깨짐.pdf`를 새로 추출해 3번씩 실행하고, 추출값이 실행마다 같은지 본다.

**끝난 기준**: 캐시 없이 추출하는 방법과, 그때 추출값이 바뀌는지 여부.

## 5. 총액 칸이 빈 영수증 (한계로 확정, 추가 작업 없음)

- 진료비 총액 칸이 비어 있어도 추출이 칸 이름의 계산식(①+②+③+④)대로 43000을 채운다
- 추출 설명을 "인쇄된 숫자만 읽고 계산하지 않는다"로 바꿔도 채워졌다. 새로 추출한 것은 수정 전 1번, 수정 후 1번이고 나머지 반복은 추출 캐시를 재사용했다
- 신뢰도도 0.98로 정상 영수증(0.996)과 구분되지 않고, 위치 정보도 칸이 아니라 표 전체를 가리킨다
- **결정:** 한계로 기록하고 최종 데이터셋의 함정 케이스에 넣지 않는다. 설계서 예외 처리 칸에 아래 문구를 쓴다

> 진료비 총액 칸이 비어 있어도 추출 단계가 칸 이름의 계산식(①+②+③+④)대로 값을 채운다. 추출 설명을 바꿔도 막히지 않았고, 이 값의 신뢰도는 high(0.98)로 정상 영수증(0.996)과 구분되지 않았으며 위치 정보도 칸이 아닌 표 전체를 가리켰다. 그래서 총액이 빈 영수증은 검산을 통과해 걸러지지 않는다.
